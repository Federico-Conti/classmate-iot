# Node-RED presence processing

The telemetry flow validates MQTT payloads, resolves the active device assignment, and accepts only a sequence newer than the last one stored for that device and boot. Rejected samples can be inspected with the optional debug node, which is disabled by default.

`RSSI_WINDOW_SIZE` sets the number of observed RSSI samples in each device's moving window (default `4`, supported values `2` through `64`). Set it in the Compose environment before starting Node-RED. Until the window has that many samples, it reports no weighted RSSI. Once complete, it weights samples from oldest to newest with `1, 2, ..., RSSI_WINDOW_SIZE` and divides by the sum of those weights. For example, `[-90, -80, -70, -60]` produces `-70` dBm. After each calculation, it removes the oldest `max(1, floor(RSSI_WINDOW_SIZE / 3))` samples, retaining the newer ones. It waits for the same number of new observed samples before calculating again; the just-calculated value still reaches classification.

Structurally valid samples with `targetObserved: false` and `rssiDbm: null` are diagnosed and discarded by the ingestion validator before `receivedAt`, device lookup, sequence persistence, and the RSSI window. Mismatched observation fields fail schema validation. The next observed sample in the same boot continues the prior window, `previusCandidate`, and `stableCount`, even if its sequence skips the discarded samples. A new observed boot or a changed child assignment resets all three. Neither silence nor target-not-observed messages alone create an exit.

The Function node classifies a complete weighted window as `IN` when it exceeds `RSSI_THRESHOLD` (default `-45` dBm) and `OUT` otherwise, including exactly `-45` dBm. The first decision sets `previusCandidate` and leaves `stableCount` at zero. Identical decisions increment the count to `RSSI_STABILITY_COUNT` (default `3`); a changed decision resets it to zero. Thus four identical decisions are required with the default count. On reaching the limit, the count resets to zero while the candidate remains unchanged; another three identical decisions can reach the limit again. Incomplete stability is sent to an optional debug node. Only after the count is reached does the flow read the child's latest durable event; it commits a different state and its outbox record atomically. SQLite generates the UUID event ID, and unchanged states or retried IDs do not duplicate history. A Node-RED restart retains durable confirmed presence while the in-memory window and stability count restart. Outbox publication to MQTT remains task 5.6; provisional decisions are not persisted or published.
